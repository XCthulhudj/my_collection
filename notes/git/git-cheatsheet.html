Git 常用命令速查

整理自本次交流：提交、推送、分支重命名、远程地址 · 简明版

一、先记住这条主线

工作区改文件 → git add 放进暂存区 → git commit 存进本地仓库 → git push 上传到云端。 commit 只存在本地，不会自动上传。

工作区→ add → 暂存区→ commit → 本地仓库→ push → 远程仓库

二、常用命令速查

分类命令作用
仓库 / 状态git init把当前文件夹初始化为 Git 仓库
git status查看哪些文件被修改、已暂存或未跟踪
提交git add .把当前目录所有改动加入暂存区
git commit -m "说明"把暂存区内容提交到本地仓库，并附提交说明
git log --oneline单行显示提交历史
分支git branch查看本地分支
git branch -M main把当前分支强制重命名为 main
git switch -c feature新建并切换到 feature 分支
git branch -vv查看分支及其跟踪的远程分支
远程git remote add origin URL关联远程仓库，命名为 origin
git remote -v查看当前远程仓库地址
git remote set-url origin URL修改远程仓库地址（云端改名后用）
git push -u origin main首次推送，同时建立跟踪关系
git push / git pull建立跟踪后，推送 / 拉取可省略参数
回退 / 对比git diff查看尚未暂存的改动
git restore 文件名撤销工作区对某文件的修改
git clone URL把远程仓库完整下载到本地

三、三个容易混淆的参数

写法含义要点
-u= --set-upstream，设置上游分支只在首次推送新分支时用；之后 git push / git pull 就能自动对应远程分支
-m重命名分支（move）目标分支已存在时会拒绝
-M强制重命名（move + force）目标分支已存在也直接覆盖，初始化仓库时常用
commit -m提交说明（message）后面跟一句描述，说明这次改了什么

四、两种典型场景

① 本地项目首次上传

git init
git add .
git commit -m "Initial commit"

git branch -M main
git remote add origin \
  https://github.com/用户名/my_collection.git
git push -u origin main

② 云端仓库改名后

git remote set-url origin \
  https://github.com/用户名/新仓库名.git

git remote -v        # 确认已改
git push             # 照常推送

五、提交说明怎么写

说明含义
Initial commit初始提交
Add xxx新增某个功能或文件
Update xxx更新某个功能
Fix xxx bug修复某个问题
Refactor xxx重构某个模块
Docs: update README更新文档
小提示：云端改名后，GitHub 一般会对旧地址做重定向，但仍建议执行 git remote set-url origin 新地址，避免之后踩坑。 另外 git commit 完成的是"本地留痕"，只有 git push 才真正上传。
